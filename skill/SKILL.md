# Vision — GLM-4.6V-Flash 图片识别

用 `glm-vision` MCP server 调智谱 GLM-4.6V-Flash 视觉模型，识别和理解图片内容。

## 前置检查

本 Skill 依赖 `glm-vision` MCP server 已接入 ZCode。若 `mcp__glm-vision__analyze_image` 工具不可用，停下告诉用户："需要先在 ZCode 配置 glm-vision MCP server（参考仓库 README 的「接入 ZCode」章节）"，不要自行用 curl 直调智谱 API。

## 核心调用

**单张图片**：调 `mcp__glm-vision__analyze_image`

| 参数 | 何时传 |
|---|---|
| `prompt` | 用户的提问，必填。用户没明说要问什么时，用 "请详细描述这张图片的内容。" |
| `media_url` | 图片位置，必填。三种形态都支持，直接透传用户给的值即可（见下方"输入识别"） |
| `media_type` | 默认 `"image"`。视频/文件场景才改（本 Skill 一般不用） |
| `thinking` | 需要复杂推理（图表分析、细节比对、推理题）时传 `true`；普通描述用默认 `false` |

`media_url` 底层会自动处理：公网 URL 原样用、本地文件读字节转 base64、裸 base64 字符串直接用。**你不需要手动转 base64**，直接把用户给的路径/URL 透传给 `media_url`。

**批量图片**：调 `mcp__glm-vision__batch_analyze_images`，参数 `media_urls`（列表）、`prompt`、`media_type`。返回每项 `{index, url, ok, result/error}`。把成功的结果按序号汇总给用户，失败的项标注原因。

## 输入识别

用户给的图片输入，按下表归到 `media_url`：

| 用户输入形态 | 怎么处理 |
|---|---|
| `http://` / `https://` 开头 | 直接当 URL 传 |
| 看起来是本地路径（含盘符 `C:\`、`/`、`./`、相对文件名） | 直接传路径，不要自己读文件。底层会自动转 base64 |
| base64 字符串（长串无路径分隔符） | 直接传，底层当裸 base64 |
| 用户说"刚才截的图"/"刚截的屏" | 优先找最近一次 screenshot skill 的输出路径；找不到就让用户给路径 |

路径不存在时工具会报错，把错误原样转述给用户即可，不要反复试。

## 输出

- 把模型的 `result` 原文转述给用户，保留模型的语言（中文提问用中文答）。
- 模型回答很长时，可以按要点分行，但不要自行删减关键信息或编造未提及的细节。
- 批量场景：用 "图1: ... / 图2: ..." 的形式逐项列出，失败的项明确标出 "图N: 识别失败（原因）"。

## 常见错误处理

| 错误信息 | 原因 | 怎么办 |
|---|---|---|
| `429 该模型当前访问量过大` | 免费模型限流 | 告诉用户稍等重试，免费模型有频率限制。批量场景尤其容易触发，建议拉开间隔 |
| `1210 图片输入格式/解析错误` | URL 拉取失败或格式不支持 | 多见于跨区/防盗链图片。建议用户换图片源或改用本地文件 |
| `环境变量 ZHIPUAI_API_KEY 未设置` | MCP server 没配 Key | 指向 README 的配置步骤 |
| 工具 `mcp__glm-vision__*` 不存在 | MCP server 没接入 | 见上方"前置检查" |

遇到表外的错误，把状态码 + 错误消息原样转述给用户，不要猜测原因。
